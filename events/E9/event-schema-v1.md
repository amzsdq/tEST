# E9 Immutable Event Schema v1

STATUS=EXPERIMENTAL
SCHEMA_VERSION=E9-EVENT-V1
PURPOSE=Make each post-E9 durable event independently sufficient to regenerate one ledger-equivalent trial row without rewriting a shared ledger.

## Required source-fact fields
- EVENT_ID: globally unique immutable identifier
- EXPERIMENT: experiment/trial identity
- SAMPLE: sample/order identity
- PROMPT_VERSION: exact applied prompt version
- PRIMARY_VARIABLE: exactly one tested variable
- RESULT: observed result, including PENDING/INCONCLUSIVE where applicable
- WRITE_OK: YES/NO/PENDING
- STATE_OK: YES/NO/PENDING
- WAKE_OK: YES/NO/PENDING
- WORK_OK: YES/NO/PENDING
- DUPLICATE: YES/NO/UNKNOWN
- NEXT: next discriminating test or terminal decision

## Optional measured source facts
- START
- END
- INTENDED_DUE
- ACTUAL_INVOCATION
- DISPATCH_OFFSET
- SCHEDULER_WRITES
- ANOMALY
- ROLLBACK
- RECOVERY

## Derived-only fields
These must not be treated as canonical event facts. They may be regenerated from source facts:
- DURATION = END - START when both exist
- CONTROL_OVERHEAD = measured/control timestamps according to the active experiment definition
- USEFUL_WORK = measured work interval according to the active experiment definition
- normalized narrative notes
- current-candidate summary

## Reconstruction rule
A ledger-equivalent row for an E9+ event is generated by copying required/optional source facts and deterministically calculating derived-only fields. Missing optional facts remain blank/UNKNOWN; they must never be invented. A materialized row/view is disposable and non-canonical.

## Immutability rule
Create each event at a unique path. Do not update an event after creation. Corrections are new events that name the superseded EVENT_ID.

## Concurrency rule
Shared historical files are not on the routine write path. Concurrent writers create distinct immutable event paths; reconciliation/materialization folds those events later.
