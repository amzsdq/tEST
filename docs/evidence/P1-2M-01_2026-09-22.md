## Bounded conclusions
1. Successful schedule write does not prove intended near wake delivery.
2. In this observed failure, preserved hourly recurrence supplied cold recovery without a new automation.
3. +2m cannot be treated as uniformly reliable from available evidence.
4. Recovery correctness and latency are separate; this sample supports eventual resume, not a tight latency SLA.

## Decision-use matrix
| Proposed decision | This case permits | This case forbids by itself | Additional evidence required |
|---|---|---|---|
| Promote +2m default | use as adverse sample in distribution | promotion from isolated +2m successes | repeated comparable +2m near-wake results |
| Remove hourly recurrence | identify recurrence as current tested recovery | claiming removal is safe | repeated equal/better recovery without recurrence |
| Add provisional scheduler write | test only as separate variable | claiming extra write caused this recovery | controlled incremental-benefit sample |
| Treat WRITE_OK as delivery | nothing | equating write acceptance with WAKE_OK | independent wake evidence |

## What this evidence does NOT support
- It does not prove every +2m occurrence fails; later +2m evidence was mixed.
- It does not prove +3m universally safe; +3m is the better tested practical default in this runtime.
- It does not establish an exact dispatch-delay distribution.
- It does not prove hourly recurrence is exactly-once.

## Counterfactual value
If recurrence had been removed when the near occurrence was missed, no tested cold continuation path would have remained. This is adverse evidence for preserving recurrence while using close-relative DTSTART.

If a provisional scheduler pre-arm had also been written, this case alone would not show the extra write caused recovery: preserved hourly recurrence already explains observed resume.

## Falsification / supersession tests
Operational weight decreases only when controlled comparable evidence shows either:
1. a lower lead class including +2m achieves repeated near-wake reliability equivalent to promoted +3m while recurrence/control policy stay unchanged; or
2. a simpler recovery mechanism removes recurrence yet demonstrates equal-or-better recovery reliability and latency without added control cost.

A single later success does not erase an adverse sample; compare distributions.
